# AI Dev Server v1.3.0 Final Release Design

## Goal

Freeze the current autonomous-development architecture as a stable v1.3.0 release after the capacity, human-handoff/status and Android-CI stability lots have passed their own validation gates.

No new runtime feature belongs in this release lot. The release change is declarative and auditable.

## Release contract

A v1.3.0 final candidate must satisfy all of the following on one immutable Git revision:

1. `VERSION` is exactly `1.3.0`.
2. `control/release.json` declares version `1.3.0`, channel `stable`, branch `main` and the six existing required gates.
3. `docs/RELEASE_V1.3.0.md` records the bounded release scope, safety invariants and exact validation requirements.
4. README exposes the read-only project-status command and documents the exceptional human-handoff behavior without suggesting that secrets be written to files.
5. The full Python suite passes.
6. The six required GitHub Actions workflows succeed on the exact final candidate revision:
   - CI
   - Validate AI Dev Server
   - Fault Injection Gate
   - Resilience Soak
   - Multi-Engine E2E Benchmark
   - Mobile Studio Real Build
7. After merge, an immutable `release/validated-v1.3.0` branch is created at the exact validated `main` revision.

## Stable scope

v1.3.0 freezes the current architecture including:

- evidence-gated persistent Goal Engine ownership;
- Generic, Flutter and Godot project execution paths;
- adaptive provider/model/phase orchestration V3;
- work-conserving finite-capacity scheduling with critical reserve isolation;
- safe persistent human handoff with automatic named-secret resume;
- read-only autonomous project status;
- Android mobile validation hardened against narrowly identified transient SDK archive corruption;
- existing fault-injection, resilience and multi-engine release gates.

## Non-goals

- Re-importing historical experimental PR stacks that are superseded by the current architecture.
- Adding new providers, engines, product features or architectural rewrites.
- Weakening a release gate to obtain a green release.
- Treating a handoff file as a place to store secret values.

## Release evidence

The validated release anchor is the exact final `main` commit after the release PR merge. Validation evidence must be fresh for that candidate lineage; an older v1.2.0 release anchor cannot be reused.
