# AI Dev Server v1.3.0 Final Release Plan

> **For agentic workers:** use superpowers:executing-plans, superpowers:test-driven-development and superpowers:verification-before-completion.

**Goal:** Produce one stable, auditable v1.3.0 candidate and freeze it at an immutable validated branch.

**Architecture:** This lot changes release metadata and documentation only. Runtime behavior is frozen after the preceding stability lots.

**Spec:** `docs/superpowers/specs/2026-09-15-release-v1.3.0-design.md`

### Task 1 — RED release contract

- [ ] Add a deterministic test requiring `VERSION == 1.3.0`.
- [ ] Require `control/release.json` version `1.3.0`, channel `stable`, branch `main`.
- [ ] Require the six existing release gates to remain unchanged.
- [ ] Require `docs/RELEASE_V1.3.0.md` and README project-status/handoff documentation.
- [ ] Run the full Python suite and capture the expected metadata/documentation RED failures.

### Task 2 — Final release metadata and docs

- [ ] Set `VERSION` to `1.3.0`.
- [ ] Set the release manifest version to `1.3.0` and channel to `stable`.
- [ ] Add `docs/RELEASE_V1.3.0.md` with scope, safety invariants, validation gates and upgrade notes.
- [ ] Update README with the read-only status command and safe external-prerequisite handoff behavior.
- [ ] Do not alter runtime code in this release lot.

### Task 3 — Final GREEN

- [ ] Run the full Python suite on the final candidate head.
- [ ] Require all six GitHub Actions gates to report `success` on that exact head.
- [ ] Review the release diff to ensure only release metadata/docs/tests changed.

### Task 4 — Publish immutable validated anchor

- [ ] Merge the release PR only after 6/6 gates are green.
- [ ] Verify `main` points at the release merge commit.
- [ ] Verify post-merge required checks are successful for the release lineage.
- [ ] Create `release/validated-v1.3.0` at the exact validated `main` revision.
- [ ] Close historical PRs #169, #166 and #167 only after their replacement PRs are merged.
